# Phase 5 — private original files and reviewed extraction

September 22, 2026. Locally verified; Phase 5 remains active.

PDF, TXT and Markdown uploads now retain an exact private original before extraction. The native upload intent fixes the property, actor, title, file name, byte count, SHA-256 and planned destination source. Storage uses a dedicated private bucket and immutable object path with no overwrite. The application verifies the retained bytes before finalization, extraction or download. A storage failure cannot become a successful import. Lost responses recover the same intent, and a missing upload resumes only from the same original. Stopped uploads cannot be revived by late completion; any late object remains private and referenced by its retained intent.

Text extraction is a separate recorded action. UTF-8 decoding preserves BOM, CRLF, Unicode and short text and rejects invalid encoding. PDF processing runs locally in a worker with its own memory/time limits, without application credentials or inherited runtime hooks. The parser receives explicitly transferred bytes and independently checks the original hash. It retains ordered page text, blank-page information, the exact combined extraction and recipe, and limitations. It runs no model or OCR and does not execute PDF actions or scripts. Corrupt/password-protected files, missing text and limits produce visible holds. The supported original limits are 10 MiB for PDFs and 256 KiB for UTF-8 text. PDFs are limited to 100 pages and 1 MiB extracted text; oversized/incomplete output is not silently accepted. The retained binary original remains the source of truth for visual review.

Each extraction has a single claim. Its receipt is retained before operator acceptance. Recovery reads an existing outcome or resumes an unclaimed request; it never repeats a running claim. An operator may stop an uncertain extraction and deliberately request a new local extraction. Late results remain attached to stopped history without reactivating it.

An operator reviews the original and exact extraction, makes any deliberate correction, and saves up to 256 KiB of reviewed text into the existing knowledge-material workflow. The native transaction saves the material version, original/extraction lineage and attributed decisions together. A forced history failure rolls all of them back. Accepting a replacement checks the current destination source version; concurrent corrections require a new review. Saving file text neither prepares embeddings nor publishes knowledge. Later manual source corrections retain the original-file ancestry. Existing reviewed publication, withdrawal and assistant-facts gates remain separate.

The interface provides original/extraction/decision history, complete paging, exact addressable files, current-property isolation and unavailable-read states. Browser storage retains only request identities and digests. Unused requests can be cancelled so delayed copies cannot save. Downloads are separately prepared and served as private, non-cacheable attachments after current access and byte checks. No reusable public or signed URL is issued, and preparation does not claim that the recipient received the file. The older upload endpoint now uses this strict retained workflow; the best-effort public-original/immediate-embedding path is retired.
