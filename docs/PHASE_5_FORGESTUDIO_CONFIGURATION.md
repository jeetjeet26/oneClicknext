# Phase 5 — ForgeStudio saved preferences

Local checkpoint, September 17, 2026. Supported studio preferences now save with current manager permission, strict field validation, an expected version and a stable decision identity. Configuration, before/after evidence and studio.configuration.saved commit together. Defaults are read-only. The UI retains failed drafts, recovers lost replies, rejects stale saves and offers explicit reload. Previous-property responses cannot replace current settings. Unsupported model/media/automatic controls were removed; choices belonging to individual generation requests stay there.

Brand voice, audience interests and amenity topics remain source inputs. Hashtag, CTA and caption preferences now enter the exact immutable context and generation prompt. Caption lengths use the smaller configured/channel limit. Hashtags and structured CTA fields that violate preferences are rejected after retaining the raw result. Prompt guidance also applies to CTA wording in captions; semantic compliance still requires content review. Manually edited drafts are reviewed separately. Older saved generation results retain their original contract and can recover without another model invocation. Mismatched request/result versions are held.

Source evidence records absent settings explicitly, so adding configuration later is detectable. Changed saved preferences invalidate the previous source snapshot. Existing content and approval history remain immutable and require the established explicit source-refresh workflow.
