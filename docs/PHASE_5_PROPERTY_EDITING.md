# Phase 5 — atomic property editing and retained changes

September 22, 2026. Locally verified; Phase 5 remains active.

Existing-property editing now saves supported facts, contacts and connection plans in one native transaction. The old partial save could update a property while contact writes failed, omit saved URLs/fields when reopening and overwrite unrelated policies with defaults. The replacement preserves fields it does not own, contact identities and creation dates, billing extensions, current provider credentials and runtime settings. Zero units remains zero; partial addresses remain usable. Empty contacts explicitly removes the saved list. Primary-contact uniqueness, complete input bounds and current manager/organization authority are enforced before changes commit.

Each save retains a private before/after snapshot, original reason, actor, exact baseline hashes and changed sections. Shared `property.setup.saved` evidence contains safe identities and hashes, not contact text. A stale draft cannot overwrite a later save. The operator can compare the latest values with the retained draft and explicitly choose which version to continue from. Lost responses reuse the same identity; a verified save receipt is separate from later property/selector refresh success. Failed reads remain visible rather than empty. History reaches beyond 1,000 records and saved changes are addressable after reload. The route property remains the editor scope even when the global selector changes; the UI names that scope and offers a deliberate switch.

Connection plans are private setup intentions, separate from actual credentials and provider status. The editor exposes only safe existing-connection metadata and labels it as recorded status, not a fresh health check. The compatibility property API no longer returns credential values. Contact editing is consolidated into the recorded editor; old unversioned community writes are retired. Once a property adopts recorded editing, database guards stop older partial property/contact writers from bypassing it. The earlier creation endpoint also rejects rewrites of already-completed onboarding. Native guards do not alter unrelated runtime settings or authorized parent cleanup.

Fact changes mark an existing assistant context stale atomically while retaining its prior content and any outstanding review requirement. Late context-builder success/failure cannot replace a newer invalidation. No scraping, embedding, model call, message or background refresh is launched by this save. The UI links to explicit assistant refresh and the other existing property tools. Property classification does not infer rental/ownership terms or reapprove a vertical profile, a brand package or a website release.
