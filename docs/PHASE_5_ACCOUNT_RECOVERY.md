# Phase 5 — recorded account recovery

September 23, 2026. Locally qualified; Phase 5 remains active.

The public recovery page now opens before authentication and without organization membership. PKCE verification uses the original browser verifier, removes the code from the displayed URL, and returns private, non-cacheable results. Password reset no longer has an unrecorded server-action write path. The email form validates bounded addresses and hides provider account details.

A reset requires a real, current Auth session whose native authentication method is recovery, issued within 15 minutes. User metadata cannot grant authority. A recovery session permits one completed reset. An existing verified second factor still requires AAL2. Revocation and expiry are checked again when Auth actually commits the password change. Requests use the existing private credential ledger, immutable events, cancellation fencing and provider-transaction proof. Lost responses recover the saved result without retaining or resubmitting passwords. Ordinary signed-in sessions cannot use the reset operation. Recovery email requests use Auth's own anti-enumeration and provider rate controls; the console does not claim recipient receipt or manufacture an authenticated requester for a public email request.
