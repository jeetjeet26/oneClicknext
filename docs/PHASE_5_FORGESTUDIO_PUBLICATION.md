# Phase 5 — ForgeStudio scheduling and publication evidence

September 17, 2026. These local scheduling and worker safeguards are qualified; complete ForgeStudio and Phase 5 remain open.

Scheduling creates every selected publication, queue job, approval/policy projection and semantic action in one transaction. Each target specifies an exact approved revision/hash, variant, account, future time and timezone. Invalid targets leave no partial schedule. Saved request identities recover lost responses. Frozen content/destination snapshots cannot be edited. Cancellation and rescheduling compare the version actually opened, hold claimed/attempted work, and update the queue, publication and action together. Reusing a safely cancelled destination creates a fresh request without colliding with its prior job.

The worker now requires one unique, immutable provider-write intent. A second worker or a lost intent response cannot grant another send. Approval, current property access, destination identity, credentials and the local preflight are checked before that permission; each worker claim uses a unique lease identity. The actual reviewed link is preserved. Expiring credentials require separate reconnection rather than an unsaved refresh inside publication. Provider exceptions, malformed acknowledgements, crashes or lost result saves cannot queue another post. Persistence retries repeat only the same receipt. A provider acknowledgement, publication, attempt, job and action result commit together. Legacy attempts remain held rather than being replayed.

Manager recovery can resume a proven before-send failure or record an existing destination post with its exact identity, URL and reviewed rationale. A saved provider intent prevents resending. Manual evidence is explicitly labelled operator attestation, not automatic provider verification. Conflicting late provider acknowledgements retain both sources and reopen a review hold. Private system receipts identify the worker; the scheduling operator is not impersonated. Human recovery decisions commit with `studio.publication.recovery_reviewed`; scheduling/cancel/reschedule have their own semantic records. Receipt history remains private and excluded from training.

The schedule and revision UI recover interrupted decisions, reject stale calendar edits and expose saved evidence. History is paginated instead of silently truncated, property switching remounts the schedule, failed history reads remain explicit, and destination selection is scoped to each account. The blanket retry path cannot send.
