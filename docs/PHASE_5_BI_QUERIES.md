# Phase 5 — retained and reviewed BI queries

September 23, 2026. Locally qualified; the BI product and holistic Phase 5 gates remain open.

The query panel now prepares a private, property-scoped request against the exact selected report. It retains the source fingerprint, safe fact snapshot, definition, question or report name and original input. An operator can choose a grouping directly or, when separately enabled, request assistant interpretation. Dates and channels can narrow the captured source; account scope cannot widen. Whole-period/day/UTC Monday week/month/channel/campaign-account groupings are supported. Rankings, forecasts, causal conclusions, deduplicated people, leases, custom expressions and arbitrary SQL are unsupported. The original unscoped browser-only history is not presented as property history or silently imported.

The user reviews and can correct a plan before calculation. Corrections retain the before/after plan, actor, revision and exact request. The server calculates only from the retained source with bi-v1 metric definitions: additive counts, cents for confirmed USD, fractional provider attribution, weighted ratios and unavailable zero denominators/currency. Empty sources produce no invented rows. All matching result groups are saved and paged in groups of 25; there is no silent 100-row limit. The chart explicitly represents the current page. Results retain source/plan/result fingerprints and remain unchanged after later imports. A result exceeding eight MiB is held for a narrower plan, never truncated.

Requests, plan corrections, calculation, stop and unused-request cancellation commit atomically with native history and shared actions: bi.query.requested, bi.query.plan_revised, bi.query.executed, bi.query.stopped and bi.query.request_cancelled. The immutable private command includes before/after state. Complete query history has count/fingerprint pagination, and the current source may fail without hiding saved results. Each query belongs to its original current property member; another member cannot take over its request or read its private questions. Property removal/transfer and broader retention remain separate gates.

Assistant interpretation is a separate, single-invocation operation. BI_QUERY_ASSISTANT_ENABLED must be true and provider configuration present before it can start. It remains disabled locally; manual query preparation/review/calculation is fully available. The provider receives the question and allowed date/channel/account scope, not fact rows. The model may only suggest a bounded plan. A native claim is saved before invoking the existing model with automatic retries disabled. Actual provider reference/model/usage/raw-reply fingerprint and bounded private raw reply are retained separately. Raw omission is explicit for oversized replies; unknown provider outcomes do not invent receipts or usage. Malformed provider metadata is rejected. A lost claim or provider acknowledgement never authorizes another model call. A late receipt cannot revive a stopped query or overwrite a reviewed correction. System events use bi.query_interpreter, never a forged human actor.

Pending browser storage contains only a request ID scoped to actor/property. Lost prepare and calculate replies recover the existing result; cancellation fences late unused requests and cannot erase a completed decision. Stale source and revision changes remain visible. Model interpretation, user approval and deterministic calculation remain distinct evidence. All shared events are training-ineligible; none is a verified commercial reward or authorization to train a model.
