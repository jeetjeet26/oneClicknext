# Phase 5 — recoverable first-time organization setup

September 22, 2026. Locally verified; Phase 5 remains active.

New accounts can now save and resume private organization/property/contact/connection-plan drafts at each step. Drafts retain exact inputs, prior and resulting state, actual actor, reason, sequence and time before an organization exists. They are separate native pre-organization records, not invented organization-scoped events. History includes complete native paging and exact earlier/current draft views. Browser storage holds only a scoped request identity, operation and digest; it does not hold private form content.

Completion requires an exact saved draft revision/hash and an explicit review. One native transaction creates the organization (including its type/legal name), binds the current unassigned profile as its admin, creates the first property, saves reviewed contacts and inactive connection plans, creates the default checklist and records the related property/organization actions. Task, contact or event failures leave no partial organization or membership and retain the private draft. Concurrent completion requests create one organization. Existing members cannot create another organization or silently move membership through onboarding. Transferred accounts cannot read or replay the old setup evidence.

The completion receipt remains reachable after membership is created. Lost draft/completion replies recover the original request; cancellation fences only unused identities. Stale tabs require renewed review. Failed reads keep private data and controls unavailable, and obsolete loading responses cannot replace newer drafts. Contact initialization is idempotent during React remounts. Incomplete contact drafts can be saved, while completion requires valid contacts and exactly one primary contact. Zero units, unknown years, city-only addresses and billing details are preserved. No timezone is guessed.

The old nontransactional onboarding endpoint and its immediate website/knowledge side effects are replaced by strict actor-bound decisions. The wizard describes integrations as inactive plans. Unsupported pre-property file uploads and false claims of document processing/model training are removed; users are directed to the qualified private file/text/website workflow after the property is saved. The completion screen links to the saved property and recorded activity. Password sign-in now chooses the actual onboarding destination for a new account, preserves local destinations for existing members and reports failed profile reads explicitly. Redirect normalization keeps navigation inside the application.

Private drafts and completion snapshots retain actual source data. Shared completion activity carries safe identities and hashes, not contact/legal-name contents. All records remain excluded from training. This work neither connects providers nor publishes knowledge.
