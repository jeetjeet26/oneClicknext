## Observation coverage is separate

The shared dashboard recorder recognizes registered page families for console, SiteForge, LumaLeasing, PropertyAudit, BrandForge, leads/TourSpark, LeadPulse, CRM, ForgeStudio, ReviewFlow, MarketVision, BI, knowledge, property/community/floorplans, integrations, reports, pipelines, settings/team and agency controls. This is route-family observation coverage, not coverage of every embedded panel, click, filter, draft edit or mutation. Unknown routes and arbitrary URL/query/resource content are not logged automatically. Each product must add its semantic actions explicitly as its complete journeys are qualified.

Page observations retry at most three times with a stable identity, retain up to 100 unconfirmed observations in the current browser session, and disclose failed/dropped recording. They are not a durable browser-session replay system; closing/reloading the page can lose unsaved observations. Recorded mutations use server transactions and do not rely on this best-effort layer. Invalid/unauthorized requests continue to use the existing security/request logs; the first shared-history increment covers the listed authorized actions.

## Product completion checklist

For each row, the development handoff must identify: required journey and action vocabulary; input and validation; actor/client/property scope; context/artifact versions; requested/approved/edited/cancelled/retried decisions; actual result and provider receipt where relevant; partial/unknown/failure states; recovery; public/operator UI; local regression evidence; remaining client/provider release gate. Every action entry names the capture site and trust level. Declaring an action name without recording and verifying it does not satisfy the checklist.

The baseline learning/evaluation use is workflow analysis, regression tests and better tools/instructions/retrieval with existing models. No training run, data export to a model provider, cross-client pooling or autonomous execution is enabled by this register.
