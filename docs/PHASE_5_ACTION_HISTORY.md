# Phase 5 — shared action history foundation

September 15, 2026. First local recording increment; comprehensive product action coverage remains open.

The console now has **Activity history** in the platform navigation. It filters by product and evidence type, shows actor, time and recorded before/after state, paginates on timestamp plus ID, and distinguishes a failed load from empty history. Property changes discard obsolete views. The UI states the current coverage explicitly.

The shared recorder recognizes registered dashboard page families without collecting query strings, arbitrary routes, resource IDs or form contents. These are browser observations, never proof that a task completed. Authentication/property checks derive the actor and product; a page observation cannot claim a server-confirmed mutation. The browser checks the persisted event acknowledgement, retries the same identity at most three times, and offers explicit retry for unconfirmed observations. Its in-memory queue is bounded at 100; failed and dropped capture are disclosed. It is not full browser-session replay and unsaved observations can be lost on close/reload. These limits remain visible in the product coverage register.

Follow-up pause/resume/stop and delivery-review decisions now write shared events in the same transaction as the business change. Events retain actor/property/product, action identity, task episode, before/after state, result and references to existing review evidence. An old pause request cannot undo a later resume. A forced event-store failure rolls back the associated mutation. Different intents cannot reuse an event UUID. Controls and reviews from one human for one workflow share a scoped episode. Provider outcomes entered by an operator are labeled operator review, not invented live verification.

Private `shared_action_events` and `shared_action_episodes` use explicit service-only grants and RLS. Scope is checked again in the recording function. Shared job, attempt and context references are checked against the same property/organization when supplied; recording neither creates nor executes a job. Events/episodes are immutable during ordinary operation, with scoped property cleanup permitted. Every record is excluded from training by default. Existing audit/security logs are preserved with their different provenance. No historic events or context were fabricated.
