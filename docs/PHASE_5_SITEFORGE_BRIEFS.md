# Phase 5 — saved direct-Codex briefs and handoff history

September 22, 2026. Locally verified; Phase 5 remains active.

SiteForge now saves exact brief snapshots, their original property context, operator and template identity. Saved briefs can be reopened after leaving the page. Editing a saved brief creates a new snapshot with its parent retained; it does not overwrite the earlier request. Branching from an older brief is explicit ancestry, not a claim that one branch is the deployed version. Copy and download save the current brief first; unchanged saved content reuses its snapshot. The actual document is built on the server using the existing SiteForge brief builder. Current property context and access are checked before saving new snapshots, and private brief text stays out of shared action records.

Handoff preparation retains the exact brief, mode and document hash. Clipboard success/failure or download initiation is recorded separately as a browser observation. A prepared payload is not a successful copy; a started download is not confirmed file receipt. Neither proves that Codex ran, a website was built, a package was installed or a site was published. Interrupted unknown outcomes remain unknown. Known unconfirmed browser reports retry with their original identity from the current browser session; closing that session can leave the saved server preparation without an observed outcome.

Lost save and preparation responses reuse the original request. Canonical input comparison prevents duplicate unchanged snapshots after database JSON key reordering. Complete snapshot and handoff paging reaches beyond 1,000 records. Failed reads remain visible, unsaved form replacement requires a deliberate choice, and delayed export responses cannot trigger clipboard/download work after changing property. Exact saved text, parent links and browser-reported outcomes remain reviewable after reload. Unsaved keystrokes are not retained.
