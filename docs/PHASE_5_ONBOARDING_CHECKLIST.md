# Phase 5 — recorded property checklist

September 22, 2026. Locally verified; Phase 5 remains active.

The property checklist now supports custom pending tasks, supported detail/status/notes/blocker edits, skipped tasks, reversible archive/restore, exact prior/current reviews and complete paged history. Each change retains its actual person, reason, immutable input, before/after state, result and time in the same database transaction. Lost replies recover the original task/decision; unused-request cancellation fences delayed writes without undoing saved changes. Stale forms keep their unsaved text for comparison and require current review. Failed reads or changed permissions remove editing controls. Pending browser storage contains only the property, request identity and digest.

Manual completion is explicitly reported progress. It does not verify a connection, approve readiness, publish knowledge, complete property setup or authorize training. Blocked tasks require an explanation; completion requires explicit confirmation. Archived tasks stay in the inventory/history but do not inflate active completion percentages. Counts and paging include all native rows and exceed the default REST row limit. Legacy tasks are identified as lacking recorded earlier reviews; their existing details become an exact retained before-state upon adoption. Existing type, assignment, due date and additional metadata are preserved by the supported editor.

Default task initialization is service-only and idempotent. It records the actual property.setup service principal, never an invented person, and never resets reviewed progress. Reviewed property setup completion attributes its two applicable tasks to the actual operator and parent setup decision atomically; archived, blocked and skipped operator tasks are not overridden. Organization/first-property completion retains its prior atomicity. The two old unversioned status mutation routes are closed. The compatibility status read delegates to the same private native contract and no longer selects integration credential rows. Obsolete third-party administrator/email instructions are removed in favor of existing property, knowledge and connection settings workflows.

Current organization, membership/manager role and exact source state are checked in the native write boundary. Adopted task identity and history are guarded against raw updates/deletion, with property cleanup allowed. A transferred property cannot silently rebind prior private evidence. Shared activity carries safe identities/hashes and explicit reported-result flags; private task content stays in native evidence. Records remain excluded from training.
