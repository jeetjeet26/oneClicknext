# Phase 5 — bounded automatic website capture

September 22, 2026. Locally verified; Phase 5 remains active.

A manager can now review and save a per-property website monitoring policy. The default is off. The scope is current and later published website-derived sources, the source-age threshold is 24–168 hours, and the daily UTC request budget is 1–5. A scheduled sweep creates at most five requests across properties. Each exact published version receives at most one request under the same policy revision. Pending, stopped, held or uncertain requests do not trigger hidden retries. A new explicit policy revision can authorize a new attempt, but earlier requests still consume the same day's budget.

The scheduler retains a private capture intent and service-attributed action atomically before any fetch. The author of the policy is its authorizer, not a fictional fetch actor. A claim and its result independently recheck the current property organization, policy revision, policy-owner permission and exact published source/origin. A withdrawn or replaced source cannot silently qualify an old request. Recovery claims a queued request at most once; already claimed work reads its retained status. The runtime pause prevents both dispatch and fetch. The existing six-hour scheduled endpoint now records paused, ready, held and uncertain outcomes without claiming publication or refreshed source timestamps.

Saving a policy change stops unfinished scheduled captures atomically with its retained before/after decision. Operator requests and ready captures remain available. Late receipts remain attached to stopped work. Policy and scheduled-action history failures roll back their associated changes. Private originals, review text, publication and search preparation retain their existing separate workflows: automatic capture never creates a reviewed material version, publishes knowledge, resets source freshness or enables training.

The UI exposes scope, age, daily budget, current permission, actual request counts and complete policy history. Each change requires a reason and explicit confirmation. Missed responses recover the exact saved decision; unused cancellation fences delayed requests. Stale edits require reloading the current policy. Failed reads remove actionable controls, property switches remount the workspace, and scheduled captures are clearly identified in the normal capture review flow. History includes retained reasons and before/after states; native paging covers more than 1,000 decisions.
