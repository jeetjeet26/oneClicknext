# Phase 5 — retained website capture and reviewed knowledge

September 22, 2026. Locally verified; Phase 5 remains active.

Community now retains one exact public page per website request. The request fixes the property, actor, URL, title, intended destination source and any earlier capture/revision. A private native record is saved before one fetch may be claimed. Recovery reads that claim or its receipt without repeating the fetch; stopping prevents a late result from becoming eligible while retaining it in history. Runtime pause is checked before claiming or contacting a page.

The static reader uses the existing public transport with DNS validation and address pinning, per-redirect validation, a 25-second limit and a 1 MiB response limit. It sends no user cookies or provider credentials, executes no scripts and follows no page links. Supported responses are UTF-8 HTML, XHTML and plain text. The complete original retains BOM/CRLF/Unicode and a byte hash; extracted text is retained separately with its parsing recipe and limitations. There is no 50,000-character clipping. Unsupported encodings/content, invalid bytes, challenge pages, missing text, response limits and uncertain fetching produce visible holds. Original content is never rendered as executable HTML. Prepared downloads return exact private bytes as non-cacheable attachments.

Review saves an explicit correction of up to 256 KiB into the private material workflow. Source version, original capture, receipt digest, actor and reason commit together with semantic action history. A concurrent destination edit is held; acceptance does not publish or prepare embeddings. Larger retained text requires an explicit shorter correction, while preserving its complete original. A refresh is a new capture linked to earlier history and the same source; accepted originals cannot be silently replaced. Later manual corrections inherit the nearest actual original. A new file original supersedes older website ancestry and a new website capture supersedes older file ancestry.

When website-derived text is explicitly published through the existing material workflow, it retains the captured URL and actual fetch time. Neither correction nor republication resets website freshness. Native integration proves an eight-day-old capture remains withheld by Luma after publication today. Existing search preparation, publication/withdrawal and complete assistant-facts review remain separate steps. Service fetch claims and receipts have distinct service attribution; operator reviews remain attributed to the actual reviewer. Private text and URL payloads are excluded from shared action events and records are not training eligible.

The UI provides complete property-scoped capture/decision paging, exact original/extracted-text review, source/capture links, lost-response recovery and cancellation of unused requests. Read failures clear selected evidence and property changes remount the workspace. The former immediate community/onboarding crawls, arbitrary completed-source creation and manual refresh are retired with review guidance. Setup retains website addresses and directs operators to capture sources after saving the property. The scheduled legacy replacement endpoint records an explicit hold without modifying sources or freshness; bounded automatic retained capture still needs its own approved system policy and qualification.
