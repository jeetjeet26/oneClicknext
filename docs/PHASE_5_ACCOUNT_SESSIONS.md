# Phase 5 — private session controls

September 23, 2026. Locally qualified; Phase 5 and the complete account product remain active.

The profile session link now opens an account-owned security page. Its actual provider session inventory, review, current/other-session sign-out, unused-request cancellation, missed-response recovery and complete history remain available without an organization. Another organization member or administrator cannot read that private history. New password sign-ins preserve the supplied browser description; unsupported legacy descriptions are labeled unavailable. Device hints are informational, not identity proof or proof a device is online.

Every operation starts from the verified token's actual actor and session, followed by native current-session verification. Revoked sessions cannot use these private security APIs even while their access token is unexpired. A bounded source hash checks session identities and factor requirements without treating ordinary refresh timestamps as a new review. Other-session sign-out explicitly covers all other sessions present when the provider executes, including newly opened ones after review; current-session sign-out leaves others alone. Existing access tokens can remain valid until expiry. This increment does not establish immediate revocation for every unrelated application API.

A native request acquires one private execution claim. Retries never receive that capability and never contact the provider again. Recording failure prevents an initial call; a lost result after execution remains recoverable from its native request. Provider acknowledgement, explicit rejection, ambiguous transport result and later state observation are distinct. Observing reviewed sessions absent from the active list never invents provider acknowledgement or causal proof. A current-session result can be recorded after its provider session is gone and recovered after a fresh sign-in. Cancellation fences only unused identities and never undoes a claimed call. Concurrent current-session claims are held. Ordinary account-menu sign-out and invitation account switching use this same recorded current-session path, replacing the menu's implicit global sign-out. An unconfirmed result preserves cookies and exposes recovery.

Session requests and events are private, actor-owned and immutable except for bounded receipt/observation updates. History uses native pagination beyond 1,000 rows with change detection. Service-only narrow projections read selected authentication facts without granting broad auth-table access. Browser requests cannot override actor/session or inject arbitrary retained fields. Access/refresh tokens, passwords, IP addresses, factor secrets and raw provider errors are excluded from the ledger and shared activity. Private reviewed session IDs stay private; organization activity receives only the request, scope and bounded outcome for a real organization. Accounts without one still retain their own private security history. These security events remain training-ineligible.

Verified second factors hold other-session mutation at low assurance. Current-session sign-out remains available. Full factor enrollment, challenge, recovery and account-wide enforcement are not completed by this boundary. Password changes/recovery still need their complete recorded lifecycle. Those controls, notification/report/connection behavior, remaining products, retention, BI, real provider/client acceptance and shared autonomy gates remain open.
