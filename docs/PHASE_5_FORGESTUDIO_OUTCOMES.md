# Phase 5 — ForgeStudio measured results

Local implementation checkpoint, September 17, 2026. This qualifies the listed results workflow, not live provider acceptance, causal attribution, all ForgeStudio journeys or Phase 5 completion.

The Results tab lists published posts with paginated observations and attributed reports. Unknown counts remain unknown; explicit zero remains zero. Each observation retains its source, timestamp and definition. Cumulative snapshots are never summed together. Provider reporting periods are not independently qualified and are labeled provider-reported snapshots; sourced operator reports explicitly describe cumulative totals since publication. Legacy metric records remain disclosed as unqualified.

Provider checks save a private request bound to the publication, exact revision, remote post, destination and credential identity. The bounded worker respects the outbound pause, rotates due posts by oldest attempt and retries only reads behind expiring fenced claims. Changed destinations or credentials hold the result. Raw provider evidence is private; console responses expose an allowlist. Missing or failed insight reads do not become zero-valued success. Operators can include/exclude observations with an exact version, required reason and atomic activity history.

Attribution requires an actually published post, a valid event time and a server-controlled 30-day window. Reported business events have a hashed source/event identity, with exact retry/conflict behavior independent of hourly subject buckets. Redirect visits are separately labeled unverified observations. Exclusion/restoration retains the original evidence and records the decision atomically. A replay cannot undo exclusion. No measurement or attributed count automatically becomes a positive training reward. Existing outcomes from the former unqualified writers are retained and marked unqualified/unknown, not deleted.

Recorded decisions: studio.metrics.requested, studio.metrics.reported, studio.metrics.reviewed and studio.attribution.reviewed. Private scheduled-read evidence distinguishes system origin; it is not comprehensive shared system-action coverage. Training stays disabled.

Verification: 315 service/API tests in 44 suites; 296 rollback SQL assertions across seven ForgeStudio suites; 23 combined browser journeys, including four new Results journeys. Full TypeScript, changed-file lint and schema stamp checks pass. 156 saved function bodies match the local schema. Advisor WARN/ERROR keys remain at the 1,333 baseline with no additions/removals. Fixture/orphan and unwritten migration-history checks are zero. Mobile result review was visually inspected. Browser checks cover lost report/review responses, explicit zero vs missing, paused requests, private evidence redaction, source-event deduplication/exclusion/restoration, older page decisions, stale review and failed-read recovery. SQL also covers scope, immutable evidence, claim fencing, changed credentials, invalid timing/counts, atomic rollback and no automatic reward.

Only local isolated fixtures and mocked providers were used. Real provider permissions, metric availability/period definitions, client source correctness, observation cycles and external acceptance remain release gates. No hosted schema update, real provider/model call, publish, send, training/export, deployment or commit occurred. Continue configuration/connections, remaining operator/system interactions and the wider product register without treating this checkpoint as phase completion.
