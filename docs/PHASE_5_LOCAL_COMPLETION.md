## Final integration changes

Calendar and email credential renewal now record actual native start/result transitions in shared activity under `integrations.credential_service`. Version-fenced audit rows determine the event; the provider actor is never misattributed to an administrator. Exact receipt replays add no duplicate events. Uncertain, revoked and superseded late results remain distinct. A history failure rolls back the credential result. Account addresses, token values, raw errors and private result digests are excluded. Legacy unscoped audits receive no fabricated attribution. These records are training-ineligible.

Calendar health now counts the complete current connection event set and all active bookings in the database. Failed, drifted, missing and cancelled events beyond the former 1,000-row sample cannot disappear from status. Closed bookings and unrelated/retired connections do not inflate the summary. Native current actor/property checks apply; a summary read failure returns an error. Outlook's manual-check limitation remains visible when reconnection is required.

Migrations: `20260924103356_phase_five_integration_service_history.sql` and `20260924104828_phase_five_calendar_summary.sql`, applied once locally. Hosted migration history was not stamped. Shared UI/types reflect the local qualification schema; hosted promotion and migration reconciliation remain separate.

The CRM transfer screen now explicitly says note delivery is unavailable and offers only supported lead preparation. Existing private note attempts remain reviewable and stoppable; they cannot gain a new send button merely from a saved lead qualification. The underlying separate-note evidence requirements are preserved.
