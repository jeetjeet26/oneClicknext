# Phase 5 — recorded widget installation and logos

September 23, 2026. Locally qualified. The holistic Phase 5 product register remains active.

LumaLeasing now retains exact installation code/key preparations privately, checks whether their key remains current, and records actual browser copy/download outcomes separately. Clipboard failure is explicit. A prepared handoff does not claim a website was installed. An old preparation remains available as historical evidence but cannot be copied as the current installation after key replacement.

Managers and administrators can replace a key with an explicit impact acknowledgment and reason. The key, private decision and safe shared action commit together. Stale decisions are held; missed replies recover the same saved result without replacing the key again. Direct legacy key writes and the old unrecorded key/logo endpoints are closed. Configuration saves now require the current manager or administrator role and same-origin requests.

Logos use the existing managed asset library: upload an original, review and approve it, then select its exact retained version for the widget. The property, revision and original hash are checked atomically. Withdrawal, archiving or changed source identity removes that library logo from subsequent public configuration responses. Clearing the selection preserves its original file and decision history. Existing manually supplied logo URLs remain part of recorded configuration settings. Cached responses in already open visitor widgets are not retroactively erased.

Both controls expose complete paged private history, stable pending-request recovery and unused-request cancellation. Shared events contain safe references/status; keys, exact handoffs, original images and staff reasons remain private. Every action remains training-ineligible. A new operation clears the earlier success message before it starts.
