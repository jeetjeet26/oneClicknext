# Phase 5 — trustworthy BI reports

September 23, 2026. Locally qualified; Phase 5 and the complete BI product gate remain open.

MultiChannel BI now reads the current and immediately preceding periods in one native database snapshot. The dashboard, channel totals, campaign table and campaign drawer share that exact source. Filters clear old figures, abort superseded requests and reject late replies. Failed reads remain visible instead of retaining older totals. Date presets count inclusive dates correctly. Campaigns retain separate channel/account identity and use explicit pagination.

The definition version is `bi-v1`: impressions and clicks are additive counts; money is summed in cents and shown as USD only when confirmed; conversions retain fractional provider attribution and are not deduplicated people or verified leases. CTR is total clicks divided by impressions, CPC is spend divided by clicks and cost per reported conversion is spend divided by conversions. A zero denominator, unconfirmed currency or percentage change from a zero baseline is unavailable. Coverage lists observed dates and source accounts; it does not claim complete provider delivery. Goal comparisons require the full matching calendar period, all accounts/channels and daily stored coverage. Broader goal lifecycle and anomaly/query qualification remain open.

A named saved report retains the reviewed filters, safe projected fact rows, property label, prior-period rows, definition version and source fingerprint. The service rechecks current property access and exact source identity before saving. Later imports or property-name changes cannot rewrite a saved report. Raw import provenance is excluded. Read-only team members with current property access may save and inspect reports; a removed member cannot read or replay them. Request identities belong to the original actor. Unused cancellation creates a tombstone that blocks a late save; a completed report cannot be erased by cancelling its request.

CSV and PDF exports use the retained source and include all campaigns, daily totals, source coverage, definitions and report references. CSV cells quote embedded commas, quotes and newlines and neutralize formula execution. PDF rows retain complete campaign/account identities across pages. The native export preparation is separate from the browser observation: `download_started` and `download_failed` are observations, not evidence of file receipt, client delivery or email. Lost responses recover native history; a prepared file starts only after an explicit browser action. Pending session storage contains request identity and bounded recovery metadata, never fact rows, report text, passwords or tokens. Browser/storage interruptions retain an unresolved state rather than inventing success.

Native report/export/history mutations and their shared action events commit atomically. The four registered actions are `bi.report.saved`, `bi.report.cancelled`, `bi.export.prepared` and `bi.export.reported`. The first three are server-confirmed decisions; the last is browser-observed. All remain training-ineligible. The retained source is future evaluation context, not a training authorization, commercial reward or evidence of autonomous success. Saved filters capture the choice used for a report; changing every live filter, opening a campaign, natural-language queries, goals, schedules and alerts still need their remaining semantic coverage.

History is property-scoped and paged in groups of 20 with a complete count and fingerprint. Concurrent changes hold subsequent pages for reload. Native report reads include every matching row up to 50,000 per period and reject larger snapshots instead of silently truncating; date ranges are at most 366 inclusive days. Private report retention currently follows property retention; product-level archive/deletion and cross-account transfer remain separate unqualified journeys.
