# Phase 5 — recorded pipeline controls

September 23, 2026. Locally qualified; real provider and whole-platform acceptance remain open.

Pipelines now supports selecting exact connected ad accounts and a reporting period, requesting an import, stopping a tracked import, creating a linked retry and recording a review of saved progress. Native decisions retain the actor, immutable request, before/after state and result together with shared action evidence. Account choices carry the displayed connection fingerprint; changed choices are held before acceptance. Source identities freeze at acceptance, and a retry retains the original relative-date anchor and source identities. It cannot silently bind another account.

The existing leased importer remains the execution engine. Current requester permission and source connections are rechecked before a worker starts; changed accounts and revoked permission are visible holds. Stops clear lease authority and reject late reports, heartbeats and writes, preserving already committed records. An external provider read already in flight may finish. Saved report fingerprints, exact row counts and batch checkpoints are separate from provider access and business outcomes. Interrupted batch recovery preserves earlier commits and avoids counting them again. Human retries create a new linked request; completed imports do not masquerade as recovery.

Worker starts, source-report retention, batch/account progress and completion produce separate service-principal history atomically with their changes. Service-origin requests remain distinguishable from human requests. Human request/stop/retry/progress-review/unused-request-cancellation actions are attributed to the current operator. Every shared event remains training-ineligible. Private source rows, lease tokens and decision notes are not copied into broad shared events.

Complete import and per-job history is paged with counts and drift detection. Lost replies recover the existing command using actor/property-scoped browser storage containing only its identity. Unused cancellation prevents a delayed request from creating work. Viewers inspect history without gaining mutation permission. Idle visible jobs refresh from saved state; a written note or unconfirmed decision suspends polling. Historical jobs remain readable and explicitly lack newer provenance; unversioned work cannot be revived as a tracked retry. Stopping an older recoverable job uses its existing lease contract.

MultiChannel BI links to these controls. Legacy manual POST entry points return a clear move-to-Pipelines response without dispatch; prior job GETs and scheduler helpers remain supported. Manual requests persist in the native queue for the enabled worker. The local worker and real delivery/provider execution remain held.
