# Phase 5 — ReviewFlow cases and staff work

Local qualification, September 17–18, 2026. Product and Phase 5 completion remain open.

The review drawer and Tickets tab now offer a working staff case workflow: explicit case creation, scoped assignment, priority and follow-up deadline, remediation progress, attributed notes, staff ticket creation/edit/completion, case resolution/dismissal and explicit reopening. Ticket and history lists page by stable cursors; team choices also page. Read failures remain visible. The ticket list no longer queries nonexistent assigned_at/resolved_by fields or presents a failed read as an empty successful queue. Legacy mismatched source/assignee joins cannot reveal another property's review or another organization's staff name.

Every mutation identifies the real operator, property, exact review source, current case version and ticket version when applicable. A saved command identity recovers lost replies; payload conflicts and stale tabs cannot overwrite newer decisions. Case/ticket state, exact private before/after revisions, append-only case history and semantic activity commit together. Browser roles cannot bypass the recorded server mutations. Ticket and case deletion are retired while property cleanup still cascades correctly.

Case closure requires actual staff-reported evidence and no unfinished staff tickets. This is not independent proof of resident satisfaction. Posted responses no longer resolve cases automatically; response transitions preserve explicit terminal case decisions. Reopening preserves prior resolution evidence in history and does not silently reopen other tickets or send a response.

Actions: review.case.created, updated, resolved, dismissed, reopened, note_added; review.ticket.created, updated, reopened. Private narrative and exact ticket revisions stay in property-scoped case evidence; the shared activity stream records safe state changes and source identity. Neither this workflow nor its data authorizes autonomous execution or training.
